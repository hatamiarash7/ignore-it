# Context

Customer profile data is stored in several service-specific files, making updates difficult to validate and query consistently.

# Decision

The profile API will use PostgreSQL as its system of record. Schema changes will be versioned and applied through reviewed migrations.

# Consequences

Constraints and transactions improve data integrity and reporting. The service gains a database dependency and must maintain backups and migration compatibility.
