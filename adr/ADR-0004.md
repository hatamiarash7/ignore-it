# Context

Applications maintain separate login flows and session rules. This creates inconsistent security behavior and duplicates account-management work.

# Decision

The web portal and internal clients will authenticate through the identity broker using OpenID Connect. APIs will validate access tokens and enforce their own authorization policies.

# Consequences

Users receive a consistent sign-in experience, and credential handling is centralized. The broker becomes a critical dependency and requires high availability and careful token configuration.
