# Context

Catalog reads dominate API traffic, while product descriptions change infrequently. Database load rises during promotional events.

# Decision

The catalog API will cache frequently requested product responses in Redis with a short time-to-live and invalidate affected entries after updates.

# Consequences

Read latency and database load should decrease during traffic spikes. Cached values may briefly lag behind writes, so cache failures must fall back to the database.
